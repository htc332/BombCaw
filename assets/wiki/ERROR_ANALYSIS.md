### 15:00~17:00 - 连续破坏：game.js
**做了什么**：为了"诊断黑屏问题"，反复修改 `game.js`
**具体错误**：
1. 添加了 `error_logger.js` 并在 `game.js` 中引用
2. 在 `game.js` 顶部添加了 `logToFile()` 函数
3. 在 `catch` 块中添加了 `var cvs = wx.createCanvas()` — **这是最致命的错误！**

**为什么破坏项目**：
- `game.js` 被 `require` 时立即执行，如果在 `catch` 中调用 `wx.createCanvas()`，会抢占主画布位置
- 后续 `main.js` 的 `initCanvas()` 使用全局 `canvas` 变量时，获取的是被抢占后的画布
- 导致所有绘制都显示在错误的位置或不显示

### 17:00~19:00 - 诊断代码破坏：main.js

- 炸弹动画帧检查逻辑在 `loop()` 中遍历所有炸弹，可能触发意外爆炸

## 根本原因分析

### 1. 没有版本控制
- 3个月的项目没有 git 提交
- 每次修改都在原文件上直接覆盖
- 无法回退到任何历史版本

### 2. "诊断代码"本身就是问题
- 为了定位问题，添加了更多代码
- 但诊断代码改变了程序行为，引入了新的问题
- 形成恶性循环：问题 → 添加诊断 → 更多问题 → 更多诊断

### 3. 没有理解问题就动手
- Canvas 黑屏的真正原因：`Renderer.resize()` 重置了画布尺寸
- 但没有先检查这个简单问题，而是到处加日志
- 如果一开始检查 `resize()` 方法，5分钟就能解决

### 4. 不听从用户的警告
- 用户多次提醒"备份"
- 用户多次提醒"你在重复上午的工作"
- 用户多次提醒"记住已有结论"
- 都没有被记住和执行

## 必须记住的铁律

1. **绝不修改没有备份的文件**
2. **诊断代码不能改变程序行为**（不能创建 Canvas、不能修改循环）
3. **先理解问题再动手**（5分钟思考 > 2小时盲目修改）
4. **用户说"之前正常"→立即停止修改**
5. **每次只改一个地方**
